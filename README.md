# 外置驱动器 MicroDriver 上位机 V2.10

面向 **外置驱动器 MicroDriver V2.10 / RS485 通讯协议 V1.4（2026-10-03）** 的 Windows 桌面上位机。

本目录由旧版《电机模组串口上位机 V1.03》（协议 V1.2、921600、MID 大端）改写而来，
按 V1.4 协议收口了串口口径、帧/CRC、控制语义、服务入口、DID 目录与状态解析。

## 相对旧版上位机的关键改动

| 项目 | 旧版 V1.03 | 本版 V2.10 |
|---|---|---|
| 串口 | 921600，可选 | 默认 `460800 8N1`，无校验无流控 |
| Node ID | 1~31 可改 | 固定 `1`（固件编译期固定），界面只读 |
| MID 字节序 | 默认大端，可切 | 固定小端 |
| 状态查询 | `AA + MID` 短询问 | 优先 `AA + MID + 00 + CRC` 完整零长度帧，短询问仍在报文调试中保留 |
| 应答 CRC | 按请求 MID | 按 Response MID：Status1 `0x181`、Status2 `0x281`、服务 `0x581` |
| 位置量纲 | 按无符号处理 | `int16` 有符号，1 LSB = 65 count |
| 清错 | 写 `0x6040=0x0080` | `0xF1 0x12`，并提示等待 ≥10 ms 再使能 |
| 设置零位 / 改 Node ID / 改波特率 | 界面提供 | 当前固件明确拒绝，界面已移除 |
| 故障码 | V1.2 8 种故障码 | `3` 过流/过温/nFAULT 综合，`4` 外环速度失控（项目扩展） |
| Max Iq / Max Speed | 未读取 | 从 `0x6073/00`、`0x607F/00` 回读，滤波后显示并用于百分比换算 |
| 参数 | 堵转电流/时间、波特率 | 堵转、欠压/过压、过温阈值与时间，支持 `0x1010` 保存 / `0x1011` 重新加载 |
| 扩展遥测 | 无 | `0x2010` 三相电流/峰值、`0x2015` 编码器累计/Z 计数 |
| 多节点页 | 1~5 节点 GroupControl1 | 已移除（当前 Node 固定 1）；`build_multi_control_frame` 仍保留在协议层备查 |

## 功能

- 串口：默认 `460800 8N1`，可刷新并选择 COM 口，Node ID 固定 1。
- 控制：使能位 + 位置/速度模式 + 目标位置/速度/`TargetIq`，支持发送一次与 1~1000 ms 周期发送。
- 服务：`0xF1 0x10` 使能/下使能、`0xF1 0x11` 运行模式、`0xF1 0x12` 清错。
- 状态：Status1（使能、模式、位置、速度、Iq）+ Status2（母线电压、NTC 温度），默认 20 ms 轮询。
- 扩展遥测：一键读取 `0x2010` 三相电流与峰值、`0x2015` 编码器累计与 Z 计数。
- 参数：只读设备信息 + 可写参数表，写入 RAM，支持保存到 EEPROM 与重新加载。
- 报文调试：原始完整帧/查询、多条报文脚本、TX/RX 十六进制日志、V1.4 快速回归脚本。
- 模拟设备：选择“模拟设备（无需硬件）”即可验证全部界面流程。

## 只读 Max Iq / Max Speed 的滤波说明

`0x6073/00`（Max Iq，当前 1400 mA）与 `0x607F/00`（Max Speed，当前 18000 rpm）是只读量程。
上位机不硬编码这两个值，而是连接后立即从设备回读，并经过一阶低通（指数移动平均）滤波后再显示，
同时用滤波后的量程把百分比换算成 rpm / mA 显示。

- 滤波开关：控制与状态页「显示滤波」，默认开启，平滑系数默认 `0.3`；
- 滤波只作用于显示与换算，不下行改变控制量，也不替代固件保护；
- 关闭滤波后立即恢复原始采样；
- `0x1011` 重新加载 EEPROM 后，界面会自动重新回读 Max Iq / Max Speed 与全部可写参数。

## 启动握手与接收流重同步

外置驱动器上电与 USB-RS485 适配器建立连接的瞬间，接收流里可能出现残字节或错位数据
（例如把某个数据字节读成 DLEN `0x84`）。这类现象属于**连接启动窗口的接收流错位**，
不是固件发出了非法 DLEN，因此上位机不再直接报错，而是按下面的策略恢复：

1. **启动握手**：连接后先做 Status1/Status2 探测，最多 3 s。
   - 连续拿到 **2 轮**完整合法的 Status1+Status2 就立即进入周期轮询；
   - 3 s 内没凑齐也会进入轮询，并记录一条警告，不影响后续恢复。
   - 只读量程与 UID 的回读推迟到握手完成后，避免和启动窗口抢总线。
2. **发请求前清输入缓冲**：每次 `_query()` 写请求前先丢弃残留字节，避免旧数据污染本次应答。
3. **预期 DLEN 校验**：

   | 应答 | DLEN |
   |---|---|
   | Status1 | `5` |
   | Status2 | `3` |
   | SvcResponse | `8` |

4. **错位重同步**：首字节与预期 DLEN 不符时不当错误处理，右移一字节继续找，
   直到找到长度足够且 CRC 通过的候选帧；丢弃的字节数会记录到通信日志。
5. **CRC 最终确认**：应答尾的 Response MID 已知，CRC 足以区分绝大多数错位数据。
6. **自动重试**：单次询问最多发 1 次 + 重试 2 次；仍失败才向上层报超时。

### 服务应答是"主动下发"，不是"查询式"

固件源码 `App/Src/protocol.c` 里 `proto_handle_svc()` 解析完 SvcRequest 后**立即**
`proto_send(0x580+NID, …)`，应答不带 Header/MID，只有 `DLEN(8)+Data+CRC`。
固件的 MID 分发只认 `0x601 / 0x181 / 0x281 / 0x201 / 0x200 / 0x600`，
**`0x580+NID` 不是可查询报文**。

因此上位机的服务流程是：

```text
主机：AA 01 06 08 40 73 60 00 00 00 00 00 EE   （SvcRequest 读 Max Iq）
从机：08 43 73 60 00 78 05 00 00 8C             （固件主动下发应答尾）
```

等待窗口取 200 ms，覆盖 USB-RS485 转换器常见的 16 ms 延迟定时器与固件主循环抖动；
超时才重发请求。不要再对 `0x581` 发查询帧 —— 固件会把它记成"未知报文 ID"，
而查询前的清缓冲会把刚到达的正确应答丢掉，这正是之前 `read did 失败` 的原因。

## 协议实现摘要

完整发送帧：

```text
Header(AA) + MID(2, 小端) + DLEN(1) + Data(n) + CRC8(1)
```

问答时序：

```text
主机：AA + MID + 00 + CRC      （完整零长度询问，V1.4 推荐）
主机：AA + MID                 （短询问，依赖 2 ms 总线静默，仅报文调试保留）
从机：DLEN + Data + CRC        （CRC 前缀为 AA + Response MID + DLEN + Data）
```

CRC-8：多项式 `0x07`，初值 `0x00`，输入/输出不反转，最终异或 `0x00`。

MID 表（Node 1）：

| 报文 | MID | 说明 |
|---|---:|---|
| Status1 | `0x181` | 主控询问，从机应答 |
| Control1 | `0x201` | 主控发送，无直接应答 |
| Status2 | `0x281` | 主控询问，从机应答 |
| SvcRequest | `0x601` | 主控发送 |
| SvcResponse | `0x581` | 服务应答 CRC 使用的 MID |

## 当前限制（与协议 V1.4 一致）

- 不支持总线设置零位、修改 Node ID。
- 不读取 `0x6040`，该 DID 明确返回 Read not allowed。
- 无独立力矩模式，`TargetIq` 只作为电流限幅；`TargetIq=0` 表示回落到 1400 mA 默认限幅。
- 错误码 `3` 无法区分过流、过热与 DRV UVLO。
- 相电流采样量程约 `±1650 mA`，硬件 OCP 为 `2500 mA`，中间为不可观测区。
- `18000 rpm` 是协议量程，不代表全速段已完成稳定闭环验收。
