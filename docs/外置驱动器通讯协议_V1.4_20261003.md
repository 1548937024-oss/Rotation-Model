## 1. V1.4 相对 V1.3 的项目扩展

V1.3 的帧、MID、状态和 DID 基础定义保持不变。V1.4 记录当前外置驱动器的具体实现口径。

| 项目 | V1.3 基础 | MicroDriver V2.10 当前实现 |
|---|---|---|
| 串口速率 | 默认速率未在本工程中完全沿用 | `460800 8N1`，这是本产品主动选择 |
| 从机写权限 | 可读、可写由实现决定 | 控制帧和部分 DID 可写 |
| 位置/速度控制 | 定义 Control1 | 已映射到位置环、速度环 |
| 力矩控制 | 定义 TargetIq | 当前只作为速度环/位置环的电流限幅，不是独立力矩模式 |
| 最大电流 | `0x6073[00]` | `1400 mA`，只读 |
| 最大速度 | `0x607F[00]` | `18000 rpm`，只读 |
| 首次使能 | 无统一规定 | 未建立零点时自动执行对齐，再继续原目标 |
| 清错 | V1.3 未定义本工程专用子功能 | `0xF1 0x12`，项目扩展 |
| 实测电流 | V1.3 无实测电流 DID | 扩展 `0x2010[01..04]` |
| 编码器累计 | V1.3 无 | 扩展 `0x2015[01..02]` |
| 速度失控错误码 | V1.3 无对应扩展码 | 项目扩展错误码 `4` |
| 设置零位 | `0xF1 0xA2` | 当前明确拒绝，返回 Abort |
| 设置 Node ID | `0xF2` | 当前明确拒绝，返回 Abort |

### 1.1 当前固件功能摘要

当前固件已经具备：

1. 上电 bring-up 后自动进入 RS485 协议从机模式。
2. 支持 Status1、Status2 状态查询。
3. 支持 Control1 和 GroupControl1 控制位置、速度。
4. 支持首次使能自动完成 D 轴吸合对齐。
5. 支持 `0xF1` 使能、运行模式、清错服务。
6. 支持 `0x40` 读 DID 和 `0x23` 写 DID。
7. 支持参数保存到 EEPROM、从 EEPROM 重新加载。
8. 支持软件最大电流限幅 `1400 mA`。
9. 支持 DRV8376H nFAULT 硬件过流、过温综合故障处理。
10. 支持故障锁存、显式清错、4 ms 冷却后重新使能。
11. 支持速度失控保护，错误码为项目扩展码 `4`。
12. 支持扩展 DID 读取三相电流和编码器累计值。

当前不包含：

1. 独立的力矩模式。
2. 总线设置零位。
3. 总线修改 Node ID。
4. 读取 `0x6040` 控制字。
5. 将堵转阈值、欠压、过压、过温参数真正接入全部运行期保护判据。

## 2. 物理层与默认参数

| 项目 | 当前值 |
|---|---|
| 接口 | RS485 半双工 |
| 波特率 | `460800 bit/s` |
| 数据位 | `8` |
| 校验 | 无 |
| 停止位 | `1` |
| 流控 | 无 |
| 默认 Node ID | `1` |
| 支持 Node ID 范围 | 协议定义 `1..31`，当前固件编译期固定为 `1` |
| 默认协议启动 | 上电自动启动 |
| 协议模式串口日志 | 静音，日志只写 RAM 镜像 |
| 首字节超时 | 短询问帧依靠 `2 ms` 总线静默收尾 |

### 2.1 上电行为

1. MCU 完成 bring-up。
2. 当前 `BOARD_FOC_BOOT_ALIGN_ENABLE=0`，上电不自动做零位对齐。
3. 进入 `460800 8N1` RS485 协议从机。
4. 上位机第一次发送使能后，如果编码器零位尚未建立，固件自动开始零位对齐。
5. 当前台架默认电机为 FS1320，首次对齐使用 `250 mA`、持续时间 `1200 ms`。
6. 对齐完成后，固件自动继续该次使能请求中的位置或速度模式，并下发原目标。

上位机第一次使能后应允许至少 `1.2 s` 的对齐时间。对齐期间，状态查询、服务请求仍可响应。

## 3. 帧格式与 CRC

### 3.1 主控发给从机

```text
AA | MID_L | MID_H | DLEN | Data[0..DLEN-1] | CRC
```

| 字段 | 长度 | 说明 |
|---|---:|---|
| Header | 1 | 固定 `0xAA` |
| MID | 2 | 报文 ID，推荐小端 |
| DLEN | 1 | Data 长度，合法范围 `0..128` |
| Data | DLEN | 报文数据 |
| CRC | 1 | CRC8 |

### 3.2 从机应答

```text
DLEN | Data[0..DLEN-1] | CRC
```

从机应答不发送 `AA` 和 MID。

但从机计算应答 CRC 时，仍然必须把以下前缀一起代入：

```text
AA | Response_MID_L | Response_MID_H | DLEN | Data
```

上位机做返回帧 CRC 校验时，必须按请求类型选择对应的 Response MID，而不是直接用请求 MID。

### 3.3 CRC8

| 参数 | 值 |
|---|---|
| 多项式 | `0x07` |
| 初值 | `0x00` |
| 输入反转 | 否 |
| 输出反转 | 否 |
| 最终异或 | 无 |
| 覆盖范围 | `AA + MID + DLEN + Data`，不含 CRC 字节本身 |

参考实现：

```c
uint8_t crc8(const uint8_t *buf, uint32_t len)
{
    uint8_t crc = 0x00U;

    for (uint32_t i = 0U; i < len; i++) {
        crc ^= buf[i];
        for (uint8_t bit = 0U; bit < 8U; bit++) {
            crc = (crc & 0x80U) ? (uint8_t)((crc << 1) ^ 0x07U)
                                : (uint8_t)(crc << 1);
        }
    }
    return crc;
}
```

### 3.4 短询问帧

协议时序中的状态询问允许只有：

```text
AA | MID_L | MID_H
```

该帧没有 DLEN、Data 和 CRC。固件在检测到 `2 ms` 帧间静默后按短询问帧处理。

上位机优先使用完整零长度帧，避免依赖超时切帧：

```text
AA | MID_L | MID_H | 00 | CRC
```

### 3.5 MID 字节序

当前固件默认按小端解析 MID：

```text
MID = MID_L | (MID_H << 8)
```

固件兼容首次出现的合法大端 MID，但 V1.4 明确要求上位机使用小端。不要在运行中混用两种字节序。

### 3.6 MID 表

以下以 Node ID `NID` 表示。当前 `NID=1`。

| 报文 | 公式 | Node 1 实际 MID | 方向 |
|---|---|---:|---|
| Status1 | `0x180 + NID` | `0x181` | 主控询问，从机应答 |
| Control1 | `0x200 + NID` | `0x201` | 主控发送，无直接应答 |
| GroupControl1 | `0x200` | `0x200` | 主控广播式控制，无应答 |
| Status2 | `0x280 + NID` | `0x281` | 主控询问，从机应答 |
| SvcRequest | `0x600 + NID` | `0x601` | 主控发送，从机应答 |
| SvcResponse | `0x580 + NID` | `0x581` | 从机应答 CRC 使用的 MID |
| SvcBroadcast | `0x600` | `0x600` | 主控广播，当前仅计数，不产生应答 |

## 4. Status1 运动状态

### 4.1 请求

| 形式 | 帧示例 |
|---|---|
| 短询问 | `AA 81 01` |
| 完整零长度询问 | `AA 81 01 00 16` |

### 4.2 应答

线上应答：

```text
05 | Byte0 | Byte1 | Byte2 | Byte3 | Byte4 | CRC
```

CRC 使用 Response MID `0x181`。

| 字节 | 位/字段 | 说明 |
|---|---|---|
| Byte0 bit7 | Enable | 功率级实际使能状态，来自 nSLEEP 实际电平 |
| Byte0 bit6 | Error | `1` 表示故障，`0` 表示无故障 |
| Byte0 bit5:0 | Mode / ErrorCode | 无故障时为模式，有故障时为错误码 |
| Byte1:2 | ActualPosition | `int16`，小端，相对对齐零点 |
| Byte3 | ActualSpeed | `int8`，百分比，有符号 |
| Byte4 | ActualIq | `int8`，百分比，当前实测为三相电流峰值占比 |

无故障时模式值：

| 值 | 模式 |
|---:|---|
| `0x00` | 位置模式，或当前没有可映射的协议运行模式 |
| `0x01` | 速度模式 |

有故障时 ErrorCode：

| 值 | 含义 |
|---:|---|
| `3` | 过流、过温或 DRV8376H nFAULT 综合故障 |
| `4` | 项目扩展：外环速度失控 |

上位机必须先判断 Byte0 bit6。只有 bit6 为 `0` 时，低 6 位才是模式。

### 4.3 应答示例

以下示例假设 Enable `1`、无故障、位置 `0`、速度 `0%`、Iq `0%`：

```text
05 80 00 00 00 00 63
```

以下示例假设 Enable `1`、无故障、位置 `10`、速度 `0%`、Iq `20%`：

```text
05 80 0A 00 00 14 93
```

## 6. Control1 和 GroupControl1

### 6.1 Control1 请求

Node 1 的 MID 为 `0x201`：

```text
AA 01 02 | 05 | MCP[0] | MCP[1] | MCP[2] | MCP[3] | MCP[4] | CRC
```

| 字节 | 字段 | 说明 |
|---|---|---|
| MCP[0] bit7 | Enable | `1` 使能，`0` 下使能 |
| MCP[0] bit5:0 | Mode | `0` 位置，`1` 速度 |
| MCP[0] bit6 | Reserved | 当前应填 `0` |
| MCP[1:2] | TargetPosition | `int16` 小端，仅位置模式使用 |
| MCP[3] | TargetSpeed | `int8`，百分比，仅速度模式使用 |
| MCP[4] | TargetIq | `int8`，百分比，作为电流限幅请求 |

Control1 没有直接应答。上位机应通过 Status1 或后续服务状态确认执行结果。

### 6.2 GroupControl1

GroupControl1 的 MID 固定为 `0x200`：

```text
AA 00 02 | DLEN | Node1_MCP[5] | Node2_MCP[5] | ... | CRC
```

当前 Node 1 取偏移 `0..4` 的 5 个字节。

GroupControl1 也没有应答。DLEN 必须覆盖本节点槽位。

### 6.3 控制语义

1. 第一次从 `Enable=0` 变为 `Enable=1` 时，固件只启动控制环，不在同一帧直接加载目标。
2. 启动后延迟约 `20 ms` 下发当帧目标，避免“使能 + 大目标”同拍冲击。
3. 如果编码器零点尚未建立，第一次使能先进入对齐，完成后自动进入请求模式。
4. 运行中修改目标时，只有目标值发生变化才重新下发轨迹。
5. 运行中改变模式时，固件先停机，再按新模式启动。
6. 非法 Mode 会保持下使能。
7. `TargetIq=0` 在当前位置实现中表示使用固件默认最大输出限幅 `1400 mA`。
8. `TargetIq` 的符号当前不用于反转转矩，固件取绝对值作为限幅。
9. 需要反转时，使用 TargetPosition 或 TargetSpeed 的符号。

### 6.4 常用控制示例

位置模式，使能，目标位置 `10 LSB`，TargetIq `20%`：

```text
AA 01 02 05 80 0A 00 00 14 4A
```

速度模式，使能，目标速度 `1%`，TargetIq `20%`：

```text
AA 01 02 05 81 00 00 01 14 A1
```

速度模式，使能，目标速度 `100%`，TargetIq `20%`：

```text
AA 01 02 05 81 00 00 64 14 15
```

下使能：

```text
AA 01 02 05 00 00 00 00 00 2D
```

## 7. 服务请求与响应

### 7.1 请求

Node 1 的 SvcRequest MID 为 `0x601`：

```text
AA 01 06 | 08 | SID | DID_L | DID_H | Sub | V0 | V1 | V2 | V3 | CRC
```

| 字节 | 字段 |
|---|---|
| Data[0] | SID |
| Data[1:2] | DID，小端 |
| Data[3] | Sub ID |
| Data[4:7] | Value，小端 32 位 |

SID：

| 值 | 含义 |
|---:|---|
| `0x40` | 读 DID |
| `0x23` | 写 DID |
| `0xF1` | 电机配置服务 |
| `0xF2` | 设置 Node ID，当前拒绝 |

### 7.2 普通 DID 响应

线上应答：

```text
08 | SRID | DID_L | DID_H | Sub | V0 | V1 | V2 | V3 | CRC
```

CRC 使用 Response MID `0x581`。

SRID：

| 值 | 含义 |
|---:|---|
| `0x43` | 读成功 |
| `0x60` | 写成功 |
| `0x80` | Abort |

### 7.3 Abort 码

| Abort Code | 含义 |
|---:|---|
| `0x06010001` | 不允许读取 |
| `0x06010002` | 不允许写入 |
| `0x06020000` | DID 不存在 |
| `0x06090030` | 写入值超出范围 |

Abort 仍使用 8 字节 Data：

```text
08 | 80 | DID_L | DID_H | Sub | A0 | A1 | A2 | A3 | CRC
```

### 7.4 `0xF1` 电机配置服务

请求 Data：

```text
F1 | Sub | Value | 00 | 00 | 00 | 00 | 00
```

响应 Data：

```text
F1 | Sub | Value | Ret | 00 | 00 | 00 | 00
```

CRC 使用 Response MID `0x581`。

上位机解析服务响应时必须先判断 Data[0]。普通 DID 响应使用 `0x43`、`0x60` 或 `0x80`，
`0xF1` 服务响应则直接以 `0xF1` 开头，不要把它按普通 SRID 解析。

| Sub | 功能 | Value | Ret |
|---:|---|---|---|
| `0x10` | 使能 | `0` 下使能，`1` 使能 | `0` 成功，`0xE5` 运行中或拒绝 |
| `0x11` | 运行模式 | `0` 位置，`1` 速度 | `0` 成功，`0xE5` 非法或拒绝 |
| `0x12` | 清错 | 建议送 `1`，实际作为回显 | `0` 成功 |
| `0xA2` | 设置零位 | 忽略 | 当前返回 Abort `0x06010002` |

`0x10 Enable=1` 的特性：

1. 若未对齐，会立即启动自动对齐。
2. 响应会立即返回，不等待 1200 ms 对齐结束。
3. 对齐完成后自动进入位置模式并保持零目标。
4. 后续 Control1 再给出真正的位置或速度目标。

`0x12 Clear Fault` 的动作：

1. 先停止 PWM 和电机输出。
2. 如果状态机处于 `FAULT_NOW`，确认故障。
3. 状态机进入 `FAULT_OVER`。
4. 4 ms 冷却后进入 `IDLE`，允许重新使能。

### 7.5 `0xF1` 常用帧

使能：

```text
AA 01 06 08 F1 10 01 00 00 00 00 00 FD
```

下使能：

```text
AA 01 06 08 F1 10 00 00 00 00 00 00 D4
```

清错：

```text
AA 01 06 08 F1 12 01 00 00 00 00 00 44
```

使能成功应答尾部：

```text
08 F1 10 01 00 00 00 00 00 E8
```

清错成功应答尾部：

```text
08 F1 12 01 00 00 00 00 00 51
```

## 8. DID 对象字典

### 8.1 只读和特殊 DID

| DID | Sub | 名称 | 类型 | 单位 | 当前值/说明 |
|---:|---:|---|---|---|---|
| `0x1018` | `0x04` | Device UID | U32 | - | 由 MCU UID 组合 |
| `0x3001` | `0x01` | 当前波特率 | U32 | bit/s | 协议模式下为 `460800` |
| `0x6040` | `0x00` | Control Word | - | - | 读取返回 Abort `0x06010001` |
| `0x6073` | `0x00` | Max Iq Current | U16 | mA | `1400`，只读 |
| `0x607F` | `0x00` | Max Speed | U16 | rpm | `18000`，只读 |

### 8.2 可写参数

这些参数写入 RAM。需要断电保持时，再写 `0x1010` 保存到 EEPROM。

| DID | Sub | 名称 | 类型 | 单位 | 范围 | 默认值 |
|---:|---:|---|---|---|---|---:|
| `0x6073` | `0x01` | Stall Current | U16 | mA | `0..3000` | `1500` |
| `0x6073` | `0x03` | Stall Time | U16 | ms | `0..65535` | `1000` |
| `0x202D` | `0x01` | UV Threshold | U16 | 0.1 V | `40..110` | `90` |
| `0x202D` | `0x02` | UV Time | U16 | ms | `0..10000` | `500` |
| `0x202D` | `0x03` | OV Threshold | U16 | 0.1 V | `80..150` | `520` |
| `0x202D` | `0x04` | OV Time | U16 | ms | `0..10000` | `500` |
| `0x2016` | `0x02` | OT Threshold | U16 | degC | `55..110` | `90` |
| `0x2016` | `0x03` | OT Time | U16 | ms | `0..60000` | `1000` |
| `0x2016` | `0x04` | OT Reset | U16 | degC | `50..110` | `75` |

当前实现说明：

1. `0x6073[01]`、`0x6073[03]`、`0x202D` 和 `0x2016` 的写操作会修改并保存参数值。
2. 当前过流保护不依赖这些堵转参数；保护入口是硬件 OCP 和 nFAULT。
3. 欠压、过压和过温配置项当前主要作为参数读写接口提供，不能在总线协议层将它们理解为全部运行期保护的唯一来源。
4. `0x6073[00]` 和 `0x607F[00]` 是只读值，EEPROM 中即使存在旧值，上电后也会被当前编译值覆盖。

### 8.3 参数保存与重新加载

| DID | 名称 | 说明 |
|---:|---|---|
| `0x1010` | Save Parameters | 将 RAM 参数写入 EEPROM，要求电机未运行 |
| `0x1011` | Reload Parameters | 从 EEPROM 读取并通过 magic、size、CRC 后覆盖 RAM |

`0x1011` 是重新加载 EEPROM 中已保存的参数，不是恢复编译期出厂默认值。

保存参数示例：

```text
AA 01 06 08 23 10 10 00 01 00 00 00 2E
```

重新加载参数示例：

```text
AA 01 06 08 23 11 10 00 01 00 00 00 F1
```

保存成功应答尾部：

```text
08 60 10 10 00 01 00 00 00 D2
```

重新加载成功应答尾部：

```text
08 60 11 10 00 01 00 00 00 0D
```

实现提示：`0x1011` 会加载整个 EEPROM 参数块。如果 EEPROM 中保留的是旧固件参数，
运行期重新加载可能把旧的 Max Iq 和 Max Speed 值带入 RAM。上位机重新加载后应再次读取
`0x6073[00]` 和 `0x607F[00]` 进行确认。当前固件在重新上电初始化时会重新应用
`1400 mA / 18000 rpm` 编译值。

### 8.4 项目扩展 DID

| DID | Sub | 名称 | 类型 | 单位 | 说明 |
|---:|---:|---|---|---|---|
| `0x2010` | `0x01` | Phase A Current | S16 | mA | 已扣零点 |
| `0x2010` | `0x02` | Phase B Current | S16 | mA | 已扣零点 |
| `0x2010` | `0x03` | Phase C Current | S16 | mA | 已扣零点 |
| `0x2010` | `0x04` | Phase Peak Current | U16 | mA | 三相绝对值最大值 |
| `0x2015` | `0x01` | Encoder Total Count | S32 | count | 32 位软件多圈累计 |
| `0x2015` | `0x02` | Encoder Z Count | U32 | count | Z 脉冲累计 |

### 8.5 DID 读写示例

读 `Max Iq Current`：

```text
AA 01 06 08 40 73 60 00 00 00 00 00 EE
```

返回值 `1400` 的应答尾部：

```text
08 43 73 60 00 78 05 00 00 8C
```

读 `Max Speed`：

```text
AA 01 06 08 40 7F 60 00 00 00 00 00 71
```

返回值 `18000` 的应答尾部：

```text
08 43 7F 60 00 50 46 00 00 56
```

写 `Stall Current=1000 mA`：

```text
AA 01 06 08 23 73 60 01 E8 03 00 00 62
```

写成功应答尾部：

```text
08 60 73 60 01 E8 03 00 00 9E
```

写 `UV Threshold=90`：

```text
AA 01 06 08 23 2D 20 01 5A 00 00 00 AD
```

## 9. 量纲、限幅与换算

### 9.1 位置

当前固件按协议正文中的有符号定义实现：

```text
-32768..+32767  ->  -520..+520 圈
4096 count/rev
1 protocol LSB = 65 encoder counts
```

上位机必须将 TargetPosition 和 ActualPosition 按 `int16` 小端处理。

### 9.2 速度

```text
TargetSpeed  -100..+100 percent
-100% -> -18000 rpm
+100% -> +18000 rpm
1%    -> 180 rpm
```

Status1 的 ActualSpeed：

```text
ActualSpeed percent = actual_rpm * 100 / 18000
```

结果夹紧到 `-100..+100`。

### 9.3 电流限幅

```text
Max Iq = 1400 mA
TargetIq 1..100% -> 14..1400 mA
TargetIq >100% or <-100% is outside normal host behavior
```

当前固件对 TargetIq 取绝对值并限制到 `1400 mA`。

`TargetIq=0` 不是“零电流”，而是回落到 `1400 mA` 默认限幅。上位机若要设置低电流限幅，应送非零百分比。

### 9.4 Status1 的 ActualIq

当前 `ActualIq` 不是 dq 变换后的 `iq_fb`，而是：

```text
实测三相电流峰值 * 100 / 1400 mA
```

该值是无符号峰值百分比，正常运行时为 `0..100`。

需要毫安绝对值时，使用项目扩展 DID `0x2010`。

当前相电流采样量程为约 `±1650 mA`，硬件 OCP 为 `2500 mA`。`1650..2500 mA`
区间是采样不可观测区，上位机不能用扩展电流 DID 或 Status1 的 ActualIq 还原该区间的真实值。

## 10. 保护、故障与清错

### 10.1 当前过流架构

| 层 | 阈值/动作 | 说明 |
|---|---|---|
| 软件最大电流限制 | `1400 mA` | 限制电流环给定和速度环输出 |
| 硬件 OCP | `2500 mA` | DRV8376H 触发 nFAULT |
| 软件响应 | nFAULT 轮询和确认 | 关 PWM、下使能、锁存故障 |

软件不再按相电流峰值逐拍执行旧式软件过流跳闸。软件保留最大电流限制。

### 10.2 nFAULT 响应时序

1. 主循环以 `1 ms` 周期轮询 nFAULT。
2. 需要连续低电平确认。
3. 最坏响应约 `2 ms`。
4. 母线低于 `9.0 V` 时，nFAULT 低电平按 DRV UVLO 处理，不作为过流。
5. 确认故障后立即关闭 PWM。
6. 将 nSLEEP 拉低，驱动器下使能。
7. 锁存 `FAULT_NOW`。
8. Status1 上报 Error `1`，ErrorCode `3`。

### 10.3 故障恢复

支持三种清错入口：

| 入口 | 说明 |
|---|---|
| `0xF1 0x12` | 上位机推荐入口 |
| Control1 下使能 | Enable bit 从 `1` 变为 `0` |
| SWD `foc ack` | 调试入口 |

标准恢复顺序：

1. 上位机发送 `0xF1 0x12`。
2. 固件先停机并确认故障。
3. 固件等待 `4 ms`。
4. 状态回到 `IDLE`。
5. 上位机重新发送使能。
6. 若重新使能时零位仍有效，直接进入请求模式。

不要在同一帧之后立即假定电机已经可运行。上位机建议至少等待 `10 ms` 后再发使能。

### 10.4 速度失控保护

速度失控保护为项目扩展：

```text
阈值    22000 rpm
确认    3 kHz 速度环连续 3 拍，约 1 ms
错误码  4
动作    关 PWM、下使能、锁存故障
```

该保护与硬件 nFAULT 分开上报。

### 10.5 状态机

固件内部状态：

| 状态 | 含义 |
|---|---|
| `IDLE` | 空闲，可启动 |
| `START_RUN` | 启动接入过程 |
| `ALIGNMENT` | D 轴吸合对齐 |
| `RUN` | 正常运行 |
| `FAULT_NOW` | 故障锁存，等待确认 |
| `FAULT_OVER` | 已确认，等待 4 ms 冷却 |
| `STOP_IDLE` | 停机过程 |

总线只能通过 Status1 的模式、Error 位和 ErrorCode观察这些状态，不能直接读取状态机名称。

## 11. 上位机适配清单

上位机按以下顺序修改最稳妥：

1. 串口固定为 `460800 8N1`，无校验、无流控。
2. Node ID 固定为 `1`。
3. 发送 MID 使用小端。
4. 接收解析第一字节直接当 DLEN，不再等待或检查 `0xAA`。
5. 应答 CRC 计算时补入 `AA + Response_MID + DLEN + Data`。
6. Status1 使用 Response MID `0x181`。
7. Status2 使用 Response MID `0x281`。
8. 服务响应使用 Response MID `0x581`。
9. 不使用短询问帧时，优先发送 `AA MID 00 CRC`。
10. 状态轮询建议 `5..20 ms`，控制帧建议 `20 ms` 周期发送。
11. Control1 没有应答，不要为 Control1 等待 ACK。
12. Control1 的 `TargetIq=0` 不表示零电流限幅，应显式发送 `1..100`。
13. 第一次使能后允许至少 1200 ms 对齐时间。
14. 对齐期间可以继续查询 Status1 和 Status2。
15. 位置目标按 `int16` 解析，不要在 V1.4 中按无符号处理。
16. 速度目标按有符号百分比解析。
17. 读取故障时先看 Status1 Byte0 bit6。
18. 清错使用 `0xF1 0x12`，等待 4 ms 冷却后再发使能。
19. 不要读取 `0x6040`，该 DID 明确返回 Read not allowed。
20. 写参数后，如果要求掉电保持，追加 `0x1010` 保存。
21. `0x1011` 是重新加载 EEPROM，不是恢复编译期默认值。
22. 当前不支持设置零位和设置 Node ID，不要在上位机中把它们显示为已成功。
23. 电流显示如使用 Status1 ActualIq，应标注为“相电流峰值占 Max Iq 百分比”。
24. 需要绝对电流显示时改用扩展 DID `0x2010`。
25. 当前 `18000 rpm` 是协议量程，不是已验收的稳定运行承诺。

## 12. 当前实测状态与已知限制

以下内容属于 2026-10-03 调试状态，不是长期协议承诺。

### 12.1 速度和位置控制

1. 当前台架 `50%` 目标，即 `9000 rpm`，已测得稳定。
2. 9000 rpm 实测约 `8980..9039 rpm`，波动约 `59 rpm` 峰峰。
3. 75% 对应 13500 rpm，当前设置下会触发速度失控保护。
4. 100% 对应 18000 rpm，当前设置下同样会触发速度失控保护。
5. 当前电流环 PI 响应正常，阶跃 300 mA 和 1000 mA 的实测超调约 1% 以内。
6. 高速问题主要在速度环、电压饱和和高速段整定，不应归因于电流环 PI。
7. 位置模式下启动和运行仍偏慢，到目标附近存在约 ±20 count 的残余抖动。
8. 上位机现阶段不要把位置到位速度或最终定位稳定性作为已验收能力。

### 12.2 首次对齐

1. 当前默认电机为 FS1320。
2. 首次使能对齐电流为 `250 mA`。
3. 对齐持续时间为 `1200 ms`。
4. 上电自动对齐当前关闭，对齐只在首次使能或调试命令中触发。

### 12.3 硬件和联调状态

1. 1 号板的 RS485 发送链路曾出现间歇性异常。
2. U5 `TPT481L1` 和 A/B 网络是重点排查对象。
3. 使用同一转换器时，另一块驱动板的 RS485 通讯正常。
4. 旧版上位机的清错帧曾出现 CRC 口径不一致，表现为发送清错时通讯断开。
5. 新上位机必须按本文档的 CRC 初值 `0x00` 和响应 MID 前缀重新实现。
6. 错误码 `3` 无法区分过流、过热和 DRV UVLO，当前这是 nFAULT 综合语义的限制。
7. LED2 黄灯的具体运行语义尚未形成正式接口定义，不应作为协议状态判断依据。
8. 相电流采样量程约 `±1650 mA`，低于硬件 OCP 的 `2500 mA`，中间存在不可观测区间。

## 13. 快速回归用例

### 13.1 连接检查

发送：

```text
AA 81 01
```

预期收到 Status1，首字节为 `05`，末字节 CRC 为对应状态计算值。

### 13.2 读最大电流

发送：

```text
AA 01 06 08 40 73 60 00 00 00 00 00 EE
```

预期返回 Data：

```text
43 73 60 00 78 05 00 00
```

含义：`0x0578 = 1400 mA`。

### 13.3 读最大速度

发送：

```text
AA 01 06 08 40 7F 60 00 00 00 00 00 71
```

预期返回 Data：

```text
43 7F 60 00 50 46 00 00
```

含义：`0x4650 = 18000 rpm`。

### 13.4 首次使能

发送：

```text
AA 01 06 08 F1 10 01 00 00 00 00 00 FD
```

预期 Data：

```text
F1 10 01 00 00 00 00 00
```

如果尚未对齐，之后应观察到电机执行吸合对齐。对齐完成后，再发送位置或速度 Control1 目标。

### 13.5 清错

发送：

```text
AA 01 06 08 F1 12 01 00 00 00 00 00 44
```

预期 Data：

```text
F1 12 01 00 00 00 00 00
```

等待至少 `4 ms`，再发送使能。

## 14. 未纳入 V1.4 的行为

以下行为不能在当前上位机中假定可用：

1. 通过总线置零位。
2. 通过总线修改 Node ID。
3. 通过 `0x6040` 控制字执行标准 CiA402 状态机。
4. 独立力矩模式。
5. Status1 的“到位”独立位。
6. 读取真实 dq 电流。
7. 修改 Max Iq 和 Max Speed。
8. 在 18000 rpm 全速范围内保证稳定闭环。
9. 将堵转阈值作为当前唯一的过流保护判据。
10. 将 `0x1011` 解释为恢复出厂默认参数。
